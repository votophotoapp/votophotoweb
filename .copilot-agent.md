# VotoPhoto - Photo Contest Website

VotoPhoto is a modern photo contest platform hosted at **votophoto.com** that enables users to participate in photography competitions, submit entries, and vote on submissions.

## Technology Stack

- **Frontend Framework**: Next.js with App Router (latest)
- **Backend/Database**: Supabase (authentication, database, real-time features)
- **Styling**: Tailwind CSS with custom design system
- **UI Components**: Radix UI primitives with custom styling
- **Icons**: Lucide React
- **Authentication**: Supabase Auth with Google OAuth integration
- **Deployment**: Vercel
- **TypeScript**: Full type safety throughout the application

## Project Structure

### Core Application (`/app`)

- **App Router**: Using Next.js 13+ app directory structure
- **Authentication Flow**: `/auth` routes handle OAuth callbacks and auth states
- **API Routes**: `/api/google/profile` for Google integration
- **Management Dashboard**: `/manage` for contest creators and profile management

### Key Features & Components

#### Authentication System

- Supabase Auth integration with Google OAuth
- One-Tap Google sign-in experience
- Protected routes using middleware
- Context-based auth state management (`/lib/auth-context.tsx`)

#### Contest Management

- Contest creation and management (`/app/manage/contests`)
- Dynamic contest pages with `[contestId]` routing
- Contest actions and dialog components

#### UI Components (`/components`)

- Custom design system built on Radix UI
- Reusable components: buttons, cards, dialogs, badges
- Authentication components: auth buttons, Google sign-in
- Layout components: app header, hero sections

#### Supabase Integration (`/lib/supabase`)

- Client-side and server-side Supabase clients
- Middleware for auth protection
- SSR support with proper cookie handling

## Development Guidelines

### File Organization

- Components should be placed in `/components` with proper categorization
- UI primitives go in `/components/ui`
- Feature-specific components stay close to their routes
- Shared utilities in `/lib`
- Type definitions should be co-located or in dedicated `.d.ts` files

### Styling Conventions

- Use Tailwind CSS classes for styling
- Follow the established design tokens and spacing
- Maintain responsive design patterns
- Use CSS variables for theme support (dark/light mode)

### Authentication Patterns

- Use the `AuthProvider` context for auth state
- Implement route protection via middleware
- Handle auth redirects properly for user experience
- Respect user session state across page refreshes

### Database/API Patterns

- Use Supabase client for database operations
- Implement proper error handling for async operations
- Use TypeScript for type-safe database queries
- Follow RESTful patterns for API routes

### State Management

- Use React Context for global state (auth, theme)
- Local component state for UI interactions
- Server components for data fetching when possible
- Client components only when necessary for interactivity

## Key Configuration Files

- `next.config.ts`: Next.js configuration
- `tailwind.config.ts`: Tailwind CSS customization
- `components.json`: shadcn/ui component configuration
- `middleware.ts`: Route protection and auth middleware
- `tsconfig.json`: TypeScript configuration

## Environment & Deployment
